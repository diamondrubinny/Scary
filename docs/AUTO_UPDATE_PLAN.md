# עדכון אוטומטי מהריפו (7.11.2026)

**הבקשה:** "תכניס עדכון אוטומטי מהריפו, ככה שכשאנחנו מעדכנים גרסה חדשה זה קופץ".

## מה בדקתי (מצב היום)
- **מספר גרסה:** `versionCode` הוא מספר הריצה ב־CI (build 200, 201…). הוא עולה תמיד, וטוב להשוואה.
- **פרסום:** ה־CI מפרסם בכל push, גם מענפי `claude/**`:
  - pre-release בשם `latest-build`;
  - הענף `apk-builds`.
- **חתימה: ממצא קריטי.**
  - אין מפתח שחרור בסודות של הריפו (בלוג: "No release key secret; the release APK is signed with the debug key").
  - ה־APK נחתם במפתח debug שנשמר ב־**Actions cache** (`android-debug-keystore-v1`).
  - GitHub מוחק cache שלא נגעו בו 7 ימים, או כשהמקום נגמר. אם זה יקרה, נוצר מפתח חדש. Android מסרב להתקין עדכון שנחתם במפתח אחר, כך שכל טלוויזיה תצטרך הסרה והתקנה מחדש, כולל איבוד ההגדרות.
  - זה נכון כבר היום גם בהתקנה ידנית. עם עדכון אוטומטי זה הופך לנקודת כשל של כל המשתמשים.

## התוכנית

### 1. CI: ערוץ "יציב"
- **רק מיזוג ל־main** מפרסם עדכון. ענפי `claude/**` ממשיכים ל־`latest-build` כמו היום, ולא קופצים אצל משתמשים.
- **Release קבוע בשם `stable`** עם:
  - `scary.apk`;
  - `update.json`: `versionCode`, `versionName`, ‏SHA-256, גודל, הערות שחרור ב־5 שפות ו־minSdk.

### 2. באפליקציה
- **בדיקה:** בעלייה, בחזרה ל־SCARY, ולכל היותר פעם ב־6 שעות, דרך מנגנון הרענון הקיים.
  - בקשה אחת קטנה ל־`update.json`, בלי שום מזהה.
  - הגדרה "בדיקת עדכונים אוטומטית" (פועלת כברירת מחדל), ו"בדיקה עכשיו".
- **חלון קופץ במסך הבית:** "גרסה חדשה של SCARY", מה חדש, ושלושה כפתורים:
  - "עדכון עכשיו";
  - "אחר כך" (שוב מחר);
  - "דילוג על הגרסה הזו".
- **הורדה:** לתיקייה הפרטית של האפליקציה, עם התקדמות וביטול.
- **התקנה:** דרך `PackageInstaller`.
  - Android תמיד מציג אישור התקנה; אפליקציה רגילה לא יכולה להתקין בשקט.
  - בפעם הראשונה צריך לאשר "התקנת אפליקציות לא מוכרות" ל־SCARY. SCARY פותח את המסך הנכון, ואם הטלוויזיה לא מציגה אותו, מסביר איך.

### 3. אבטחה
- **רק HTTPS,** ורק לרשימה סגורה של שרתים: `github.com` ושרתי הקבצים של GitHub.
- **לפני התקנה SCARY בודק:**
  - SHA-256 וגודל, מול `update.json`;
  - שם החבילה;
  - שה־`versionCode` גבוה מהמותקן (אין שנמוך);
  - שתעודת החתימה זהה לזו של האפליקציה המותקנת.
- **גם אם `update.json` זויף,** Android עצמו לא יתקין APK שלא נחתם במפתח שלנו.
- **ההרשאה החדשה:** `REQUEST_INSTALL_PACKAGES`.
  - Google Play לא מתיר עדכון עצמי. אם SCARY יעלה ל־Play, צריך לכבות את זה בגרסה של Play. **דורש אימות מול מדיניות Play.**

### 4. פרטיות
- **GitHub רואה את כתובת ה־IP** בבקשה. לא נשלח שום מזהה.
- **עדכון של PRIVACY.md** (GitHub כצד שלישי) ושל הטקסט באפליקציה ב־5 שפות. **דורש בדיקה משפטית.**

### 5. בדיקות
- **יחידה:** השוואת גרסאות, פענוח `update.json` (קלט עוין), כללי "אחר כך" ו"דילוג", ורשימת השרתים.
- **UI:** החלון קופץ עם `update.json` מקומי, והכפתורים פועלים.
- **ידנית בטלוויזיה:** עדכון אמיתי מ־build N ל־N+1.

## החלטות (7.11.2026)
- **מפתח החתימה:** נשאר ב־cache. נוספה ריצה שבועית (`.github/workflows/signing-key.yml`) שקוראת אותו, כדי ש־GitHub לא ימחק אותו, ובודקת שהוא עדיין המפתח הרשמי. ריצה שנכשלת היא האזהרה.
- **ערוץ:** רק מיזוג ל־main, ברפו הרשמי.

## אבטחה מול forks (בקשה: "שאם יעשו fork, לא יוכלו לשלוח עדכונים אוטומטיים למשתמשים של SCARY")
- **הכתובת קבועה באפליקציה:** `Updates.MANIFEST_URL` ו־`APK_URL` מצביעים ל־`diamondrubinny/Scary`, ערוץ `stable`.
  - fork שמשנה אותן משנה רק את הגרסאות שהוא עצמו בונה.
  - SCARY שהותקן מהרפו הרשמי מקשיב רק לו.
- **ה־manifest צריך לומר במפורש** `repository: diamondrubinny/Scary`, ‏`channel: stable` ו־`package: io.github.diamondrubinny.scary`.
- **תעודת החתימה נעוצה באפליקציה** (`OFFICIAL_CERT_SHA256`). APK שנחתם במפתח אחר נדחה עוד לפני Android. ‏Android עצמו ממילא דוחה עדכון במפתח אחר.
- **build של fork** (נחתם במפתח שלו) מזהה שהוא לא רשמי ולא מחפש עדכונים בכלל.
- **CI:**
  - מפרסם `stable` רק ב־push ל־main ברפו הרשמי, ורק אם ה־APK חתום במפתח הרשמי. אחרת הצעד נכשל ולא מפרסם.
  - pull request מ־fork לא מקבל את מפתח החתימה מה־cache, ונבנה במפתח חד־פעמי.
  - ל־pull request יש token לקריאה בלבד, ולכן הוא לא יכול לפרסם release.
- **סיכון שנשאר:** GitHub מאפשר ל־pull request מ־fork לקרוא cache של הענף הראשי, ו־pull request יכול לשנות את קובץ ה־workflow שלו.
  - כלומר, מי שמגיש PR זדוני, ו־GitHub מריץ אותו, יכול להוציא את המפתח מה־cache.
  - עם המפתח הוא עדיין לא יכול לפרסם עדכון בערוץ הרשמי, אבל הוא יכול להפיץ APK ש"מתעדכן" מעל SCARY בדרכים אחרות.
  - **מה לעשות (בהגדרות הריפו, ללא קוד):** Settings ← Actions ← General ← "Fork pull request workflows from outside collaborators" ← **"Require approval for all external contributors"**. כך שום PR מ־fork לא רץ בלי אישור שלכם.
  - **הפתרון המלא:** להעביר את המפתח מה־cache לסודות של הריפו, כי PR מ־fork לא מקבל סודות.
